# ISBN 기반 도서 정보 조사 도우미 검토

조사일: 2026-10-28. 요청의 `isdn`은 ISBN으로 해석했다. 이 문서는 조사와 설계 제안이며 기능 구현은 포함하지 않는다.

후속 [Codex 조사 도우미 설계·구현 계획](isbn-helper-plan.md)에서 제품 흐름과 구현 범위를 구체화했다. Codex CLI만을 대상으로 하며, 재시도·평가 표본 등 구체적인 구현 결정은 후속 계획을 따른다.

## 결론

이 기능은 **사용자가 검색하고 옮겨 적는 수고를 줄이는 조사 도우미**다. 웹검색 결과의 사실 정확성을 앱이 보증하는 것이 목적은 아니다. AI가 조사한 내용을 출처와 함께 제안하면, 사용자가 맞는지 보고 폼에 반영한 뒤 필요한 부분을 수정한다.

**개인용 데스크탑 앱에서는 사용자가 설치·로그인한 코딩 에이전트 CLI로 웹검색을 수행하고, 출처가 붙은 입력 초안을 돌려받는 방식을 먼저 검증할 가치가 있다.** 여러 국가의 API 키를 준비하고 사이트별 파서를 유지하는 부담을 줄이며, 한국·일본 출판사와 서점의 자료를 함께 찾을 수 있기 때문이다.

다만 CLI가 API보다 정확하거나 수록 범위가 넓다는 사실을 이번 조사로 입증한 것은 아니다. 검색에도 미색인 페이지, 접근 차단, 판본 혼동이 있다. 사용자 흐름은 **ISBN 입력 → AI 조사 → 출처와 함께 후보 추천 → 사용자가 확인하고 `폼에 반영` 클릭 → 폼에서 필요한 항목 수정 → 사용자가 저장**이다. 검색이 끝났다는 이유만으로 폼을 변경하지 않는다. 추천 결과는 “이런 내용으로 조사했는데, 이 책이 맞나요?”라는 확인 자료이며, 반영 후에도 모든 입력 항목은 기존처럼 편집할 수 있다. 에이전트에 DB 수정 권한을 주는 형태는 필요하지 않다.

초기에는 Codex CLI 어댑터 하나와 텍스트 필드만 다룬다. API 연동을 선행 조건으로 만들지 않고, 일본 NDL 등은 비교 실험 또는 나중의 빠른 조회 경로로 남긴다. 이미 CLI를 쓰는 현재 사용자에게는 적합하지만, 일반 사용자 배포에서는 CLI 설치·로그인·사용량 관리가 진입 장벽이다.

NDL은 이용 목적과 데이터 제공기관에 따라 조건이 다르다. 개인 비영리 이용과 상용 배포를 같은 조건으로 가정하지 않는다. [NDL 이용 안내](https://ndlsearch.ndl.go.jp/help/api)

따라서 문제는 API 개수보다 **실제 보유 도서에서의 정확한 판본 적중률, 누락 필드, 설정 부담, 서비스 지속성**이다. Google Books 같은 범용 서비스를 기본값으로 정하는 것도 한국·일본 도서 표본 비교 없이는 근거가 부족하다. 이번 검토는 각 API의 전체 수록량을 비교한 전수조사가 아니다.

## 2. CLI 웹검색 방식의 적합성

### 얻을 수 있는 것과 남는 비용

- 출판사·도서관·서점 검색 결과를 한 번에 해석하고 서로 다른 필드 형식을 정리할 수 있다.
- 개별 서점 API 키 없이 에이전트의 검색 도구를 사용할 수 있다. 그러나 CLI 자체의 인증·구독 또는 API 과금은 남는다.
- 사이트마다 HTML 파서를 만드는 비용은 줄지만, 검색 도구 변경·CLI 버전·응답 포맷·로그인 만료 대응은 필요하다.
- 웹검색이 사이트 접근 제한이나 데이터 이용 조건을 없애 주지는 않는다. 차단된 페이지는 실패로 처리한다.
- 제목만 같은 책, 원서와 번역서, 종이책과 전자책, 세트와 낱권이 섞일 수 있다. JSON 스키마 준수는 사실 정확성의 증거가 아니다.
- 한 권마다 모델 호출과 검색이 발생한다. 지연과 사용량은 모델·플랜·검색 횟수에 따라 달라지므로 무료 또는 즉시 완료를 약속할 수 없다.

### 실행 후보 비교

| CLI | 비대화형 실행·결과 | 웹검색 및 주의점 | 우선순위 |
| --- | --- | --- | --- |
| Codex | `codex exec`, `--json` 이벤트, `--output-schema` 최종 구조화 응답 지원 | 실시간 검색을 명시적으로 켤 수 있다. 기본 캐시 검색과 구분해야 한다. | 로컬 설치와 옵션 확인을 마친 첫 후보 |
| Claude Code | `claude -p`, JSON 출력, `--json-schema`; 구조화 값은 `structured_output`에 위치 | WebSearch/WebFetch 사용 가능 여부와 허용 도구를 실행 환경에서 확인해야 한다. 결과 필드 부재도 오류로 처리한다. | 사용자가 이미 설치·인증한 경우 후속 후보 |
| Gemini CLI | `-p`, `--output-format json` 또는 `stream-json` | `google_web_search` 제공. JSON 출력의 `response` 문자열과 도서 스키마에 맞는 JSON은 다른 층위다. | 동일 표본의 검색 품질을 비교할 후속 후보 |

근거: [Codex 비대화형 실행](https://learn.chatgpt.com/docs/non-interactive-mode), [Codex 웹검색](https://learn.chatgpt.com/docs/web-search), [Claude 비대화형 실행](https://code.claude.com/docs/en/headless), [Gemini headless](https://geminicli.com/docs/cli/headless/), [Gemini 웹검색](https://geminicli.com/docs/tools/web-search/).

로컬에서는 `codex-cli 0.164.0`과 관련 도움말을 확인했다. `codex`와 `gemini`가 현재 셸 PATH에서 발견되었고 `claude`는 발견되지 않았다. 앱에서의 PATH, 로그인 상태, 실제 검색 성공은 확인하지 않았다. CLI 검색 품질의 우열도 아직 판단하지 않는다.

### Codex 실행 형태 제안

아래는 설치된 CLI 도움말과 공식 문서에 근거한 **실험용 예시**다. 이번 조사에서 모델 실행을 수행한 명령은 아니다. `lookup.schema.json`과 `lookup.prompt.txt`는 향후 실험에서 준비할 파일이다.

```sh
codex --search -a never exec \
  --sandbox read-only \
  --ephemeral \
  --skip-git-repo-check \
  --ignore-user-config \
  --cd "$LOOKUP_WORK_DIR" \
  --output-schema "$LOOKUP_WORK_DIR/lookup.schema.json" \
  --json \
  -o "$LOOKUP_WORK_DIR/result.json" \
  - < "$LOOKUP_WORK_DIR/lookup.prompt.txt"
```

앱에서는 셸 문자열을 조합하지 않고 고정 실행 파일과 인자 배열로 프로세스를 생성한다. ISBN은 검증한 숫자 데이터로만 전달한다. stdout의 JSONL은 진행 이벤트이며, 최종 도서 객체는 별도로 파싱·검증한다. 종료 코드 0만으로 검색·필드 검증 성공을 판단하지 않는다.

`read-only`는 파일을 읽을 수 없다는 뜻이 아니다. 빈 작업 디렉터리도 홈 디렉터리 접근 차단을 보장하지 않는다. 전용 실행 설정과 최소 도구 권한, 필요시 OS 수준 파일 접근 제한을 별도로 검증해야 한다. `--ignore-user-config` 역시 모든 플러그인·환경·자격증명의 격리를 보장한다고 가정하지 않는다. 앱 데이터·백업·복호화 키에 접근할 수 없는 상태를 목표로 삼고 실제 파일 읽기 거부 시험을 한다.

인증은 사용자가 CLI에서 수행하고 앱은 토큰 파일 내용을 읽거나 복사하지 않는다. 프로세스에는 ISBN과 필요한 공개 서지 정보만 전달한다. 사용자 메모·구매내역·전체 서재를 프롬프트에 포함할 이유는 없다.

## 3. 도우미의 역할과 기본 입력 검사

앱이 확인할 수 있는 형식과 AI가 조사한 사실을 구분한다. ISBN 체크섬, JSON 구조, 날짜 형식은 코드로 검사한다. 제목·저자·출판사·판본이 실제로 맞는지는 사용자가 출처와 추천 내용을 보고 판단한다. 사이트별 재수집·본문 대조 엔진이나 `verified` 판정을 초기 요구사항으로 두지 않는다.

1. ISBN의 하이픈·공백을 정리하고 ISBN10/13 체크섬을 검사한다. 유효한 ISBN10은 ISBN13으로 정규화한다.
2. AI에는 ISBN으로 검색하고 출판사·도서관·서점 자료를 참고하도록 요청한다. 찾은 도서 정보와 출처 링크, 헷갈리는 부분을 함께 반환하게 한다.
3. 검색 결과에 별도 ISBN이 있으면 요청 ISBN과 문자열을 비교해 불일치를 알려준다. 일치하더라도 내용의 정확성이 검증되었다고 표시하지 않는다.
4. 여러 판본이나 서로 다른 날짜가 발견되면 후보 또는 짧은 주의사항으로 보여준다. 모르는 필드는 비워 두도록 요청한다. 이러한 프롬프트는 정확성 보장이 아니다.
5. 사용자가 `폼에 반영`을 눌러야 폼을 변경한다. 반영 후에도 모든 항목을 수정할 수 있고, 저장은 사용자가 별도로 한다.

출처 링크는 사용자가 판단할 때 참고하는 자료다. 앱이 모든 페이지를 다시 읽어 필드별 사실을 인증하는 기능까지 만들 필요는 없다. 결과는 일관되게 “조사한 정보”로 제시하고 확정된 정답처럼 표현하지 않는다.

### 사용자가 선택해 폼에 반영할 필드

| 현재 필드 | 적용 규칙 |
| --- | --- |
| `book_name` | AI가 조사한 제목·권차를 제안한다. 홍보 문구를 제목에 섞지 않는다. |
| `isbn13` | 앱이 정규화한 요청 ISBN. AI가 보고한 ISBN이 다르면 사용자에게 알린다. |
| `author` | 저자와 역자 등의 역할을 초안에서 구분하고, 현재 문자열 필드에 적용하는 표시 규칙을 정한다. |
| `publisher` | 해당 판본 출판사. 판매 서점 이름으로 대체하지 않는다. |
| `publication_date` | 조사 결과에 일 단위 날짜가 있을 때 제안한다. 연월뿐이면 날짜를 만들어 넣지 않는다. |
| `topic` | 서점 분류와 사용자 분류가 다를 수 있으므로 초기 추천의 폼 반영 대상에서 제외한다. |
| 구매 가격·통화·날짜·장소·상태·메모·중복 표시 | 개인 소장 정보이므로 검색으로 채우지 않는다. 특히 정가를 구매 가격에 넣지 않는다. |
| 표지 | 첫 버전에 수집·미리보기·선택 반영을 포함한다. 반영 후 파일 교체·제거가 가능하다. |

내부 초안에는 요청 식별자, 요청 ISBN, 추천 필드, 출처 링크, 짧은 주의사항을 둔다. AI가 별도 ISBN을 찾았다면 함께 표시한다. 필드별 증거 구조나 신뢰도 점수는 필수로 두지 않는다. 임의 키와 과도한 문자열 길이를 거부한다. 영속 `Book`과 초안 타입은 분리한다.

표지 수집 시 URL을 그대로 렌더러에서 표시하지 않는다. 다운로드 허용 조건을 확인하고, URL·리다이렉트·내부망 주소를 검사한 뒤 크기와 이미지 형식을 검증하여 기존 로컬 표지 저장 파이프라인으로 변환한다. 메타데이터 조회 허용과 이미지 복제·저장 허용은 같은 판단이 아니다.

## 4. 현재 코드와 연결할 위치

현재 체크아웃을 직접 읽어 확인한 내용이다.

- [`contracts/book.ts`](../contracts/book.ts): 필요한 기본 서지 필드가 이미 있다. 초기 텍스트 추천과 폼 반영에 DB 필드 추가는 필요하지 않다.
- [`BookForm.tsx`](../src/features/books/components/BookForm.tsx): React Hook Form 기반 수동 입력이다. 조회 결과를 `setValue` 등으로 적용할 위치이며, 검색을 시작한 뒤 사용자가 고친 필드는 덮어쓰지 않아야 한다.
- [`form-schema.ts`](../src/features/books/model/form-schema.ts), [`book-schema.ts`](../desktop/library/book-schema.ts): ISBN은 현재 문자열이며 체크섬 검증은 없다. 날짜는 유효한 `YYYY-MM-DD`만 허용한다. 검색 입력 정규화는 추가하되 기존 저장 도서를 일괄 거부하는 변경은 피한다.
- [`contracts/desktop.ts`](../contracts/desktop.ts): 조회 작업 명령이 없다. 프로세스 실행을 렌더러에 넣지 않고 계약을 확장해야 한다.
- [`command-service.ts`](../desktop/application/command-service.ts): 모든 요청이 하나의 직렬 큐를 통과한다. 여기에 긴 검색을 `await`하면 도서 조회·잠금까지 지연될 수 있다.
- [`contracts/cover.ts`](../contracts/cover.ts): 로컬 JPEG/WebP 표지 업로드 계약이 있다. 명령 처리기는 `image_url` 입력을 거부하므로 검색한 URL을 저장하는 방식은 현 구조와 맞지 않는다.

권장 배치:

```text
contracts/book-lookup.ts                조회 요청·작업 상태·초안 계약
desktop/book-lookup/                     작업 관리자·CLI 어댑터·결과 검증
src/features/book-lookup/                조회 UI·작업 상태·미리보기
src/pages/library/                      조회 기능과 books 폼을 조합
```

이는 제안 경로이며 아직 생성하지 않았다. 기능 간 import를 금지하는 기존 규칙에 따라 `books`에서 `book-lookup` 내부를 직접 호출하지 않는다. 페이지가 공개 API와 콜백으로 연결한다. 실제 폼 옆 버튼은 슬롯 또는 페이지에서 전달한 액션으로 배치할 수 있다. 구조 검사 스크립트에도 새 데스크탑 모듈의 허용 의존 관계를 명시해야 한다.

명령은 `lookupStart → jobId`, `lookupStatus`, `lookupCancel`처럼 짧게 끝낸다. 검색 프로세스는 저장 큐 밖에서 실행하되 시작·결과 반환 때 잠금과 요청 소유권을 검사한다. 잠금·초기화·종료 시 작업 취소 및 세대 번호 변경으로 늦게 도착한 결과를 무효화한다. 취소 명령도 검색 완료를 기다리는 큐에 갇히지 않게 한다.

조회 상태는 `queued/running/succeeded/not_found/failed/cancelled`로 구분하고, 작업 성공은 추천 결과를 받았다는 뜻이며 사실 정확성을 뜻하지 않는다. 같은 ISBN 중복 실행은 합치고 첫 버전은 동시 작업 1개로 제한한다. 제안 초기 제한은 전체 90초, 앱이 관리하는 재시도 1회다. 검색 횟수·토큰 제한을 CLI가 강제하지 못하면 프롬프트상의 요청을 하드 제한으로 표시하지 않는다.

GUI로 실행된 macOS 앱은 터미널의 nvm PATH를 그대로 받는다고 가정할 수 없다. 설정에서 CLI 절대 경로를 선택·검증하고 버전·인증 오류를 알려야 한다. 자동 설치나 로그인 팝업을 조회 중에 시작하지 않는다. 앱이 띄운 자식 프로세스만 취소하며, 다른 사용 중인 CLI 세션을 종료하지 않는다.

## 5. 사용자 흐름

1. 설정에서 사용할 CLI와 실행 파일 경로를 선택하고 연결을 확인한다. ISBN과 공개 서지정보가 외부 AI 서비스로 전송됨을 짧게 안내한다.
2. 도서 폼의 ISBN 옆 `정보 찾기`를 누른다. 진행 상태와 취소 버튼을 제공한다.
3. “이런 도서 정보를 찾았습니다. 이 책이 맞나요?”라는 추천 결과에서 제목·저자·출판사·출간일과 출처 링크를 보여준다. 충돌이나 ISBN 미확인은 명시한다. 이 단계에서는 폼을 변경하지 않는다.
4. 사용자가 후보를 확인하고 `폼에 반영`을 누르면 추천 정보를 폼에 넣는다. 기존 입력값이 있는 경우 변경될 내용을 확인할 수 있게 하고, 검색 중 사용자가 수정한 값을 조용히 덮어쓰지 않는다.
5. 반영된 폼에서 제목·저자·출판사·날짜 등 원하는 항목을 부분 수정할 수 있다. AI가 추천한 값도 일반 입력값과 동일하게 편집할 수 있으며, 사용자가 기존 `저장` 버튼을 눌러야 도서 데이터가 저장된다.
6. 미검색·인증 만료·한도 초과·시간 초과는 구분해서 표시하고 수동 입력을 계속할 수 있게 한다.

일반 사용자를 위한 설명은 화면 전체를 차지하는 패널 대신 짧은 상태 문구와 필요할 때 여는 도움말로 둔다. 개인정보가 포함될 수 있는 전체 CLI 원시 로그를 기본 UI나 영구 로그에 남기지 않는다.

## 6. 구현 전에 할 작은 비교 실험

실제 보유 도서의 정답 데이터 없이 “한국·일본에 더 좋다”를 확정하지 않는다. 다음은 아직 실행하지 않은 평가 계획이다.

- 한국 20권·일본 20권으로 시작한다. 최근·구간, 일반서·만화·전문서, 번역서·개정판·세트·절판 도서를 섞는다. 표지 수집 성공·실패와 반영 후 교체도 함께 평가한다.
- 사람이 ISBN·판본·핵심 필드의 정답을 확인한다. 개인 구매 정보는 필요 없다.
- 동일 표본을 Codex 검색 단독과 접근 가능한 국내 API/NDL에 넣는다. 발급되지 않은 키가 필요한 경로는 “평가 불가”로 표시하고 검색 실패로 집계하지 않는다.
- 측정값은 정확 ISBN/판본 적중률, 필드 정확도·누락률, 출처가 실제로 뒷받침하는 비율, 잘못 채운 필드 수, 수동 수정 시간, p50/p95 대기 시간, 사용량·확인 가능한 비용이다.
- 일부 표본은 반복 실행해 결과 변동을 기록한다. CLI·모델·검색 모드·실행 날짜를 남겨 재현 조건을 고정한다.

제안 통과 기준은 **사용자 클릭 없이 폼이 변경되지 않을 것, 반영 후 부분 수정이 가능할 것, 사용자 저장 전에는 DB가 변경되지 않을 것, 수동 검색·입력 대비 수고가 줄어들 것**다. 지연 기준은 우선 p95 60초 이하를 목표로 측정하되 90초에서 중단한다. 이는 관측 결과나 서비스 보장이 아닌 제품 판단용 목표다. 추천 오류와 수정량은 도우미의 유용성을 판단하는 지표로 기록하며, 사실 오류 0건을 기능의 보장이나 출시 조건으로 두지 않는다.

추가 회귀 시나리오는 잘못된 ISBN, ISBN 불일치, 날짜가 연월뿐인 결과, 여러 권 후보, JSON 오류, 인증 만료, 네트워크 차단, 취소·잠금 후 늦은 응답, 검색 도중 수동 편집, 추천 반영 후 부분 수정·저장, 추천을 반영하지 않고 닫기, 악성 페이지의 명령 유도다. 네이티브 앱에서 프로세스 시작·취소·PATH·잠금 동작을 확인해야 하며 브라우저 테스트만으로 완료 판정하지 않는다.

## 7. 권고 범위와 미확인 사항

첫 구현 후보는 **Codex CLI 1개 + ISBN 형식 검사 + 조사 결과·표지와 출처 제시 + 사용자 선택 반영·부분 수정 + 취소/시간 제한**이다. API 전체 통합, 대량 자동 등록, 가격 추정, 영구 검색 캐시는 뒤로 미룬다. 이후 측정 결과에 따라 NDL 또는 국내 API 하나를 빠른 보완 경로로 추가한다.

이번에 수행한 것은 공식 웹문서·운영 공지 조사, 현재 소스 구조 확인, 로컬 Codex 버전·도움말 확인이다. API 키 발급, 인증된 API 실호출, CLI를 통한 ISBN 검색 실행, 대표 도서 벤치마크, 앱 기능 구현·네이티브 검증은 수행하지 않았다. 따라서 추천은 구조적 적합성에 대한 판단이며, 정확도·속도·비용 우위는 후속 실험으로 결정한다.
