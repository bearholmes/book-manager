# 데이터와 백업

[문서 목록](README.md)

## 저장과 잠금

도서는 운영체제의 앱 데이터 디렉터리 아래 `ReadingDesk/books.vault`에 AES-256-GCM으로 암호화해 저장합니다.
암호화 키는 운영체제 보안 저장소에서 관리합니다. PIN 설정 여부와 관계없이 파일 암호화가 적용됩니다.

표지는 JPG·PNG·WebP 파일(최대 20MiB)을 첨부합니다. 목록의 최대 표시 영역 320×400px와
2배 화면 배율에 맞춰 최대 640×800px 안으로 줄이고, 비율을 유지한 채 WebP로 압축합니다.
WebP 인코딩을 지원하지 않는 환경에서는 JPEG로 저장합니다. 작은 원본은 확대하지 않습니다.
압축한 표지만 최대 128KiB로 보관하며 원본과 촬영 메타데이터는 저장하지 않습니다.

표지는 `ReadingDesk/covers/<식별자>.vault`에 AES-256-GCM으로 암호화한 바이너리 파일로 저장하고,
도서에는 식별자만 연결합니다. Base64는 화면과 메인 프로세스 사이의 임시 전송과 암호화 백업 내부에만
사용하며 로컬 도서 데이터에 이미지 문자열을 넣지 않습니다. 같은 표지는 중복 저장하지 않습니다.
표지 교체·제거, 도서 삭제, 복원·초기화 시 더 이상 쓰지 않는 표지 파일도 정리합니다.
PIN 잠금 중에는 표지 읽기도 차단하고 화면의 이미지 캐시와 임시 주소를 해제합니다.

기존 URL 기록은 보존하지만 외부 이미지는 자동으로 요청하지 않습니다. 해당 도서 수정에서
이미지 파일을 첨부하면 로컬 표지로 교체됩니다.

4자리 PIN은 앱 화면을 잠급니다. 사용 시 앱 시작 때 잠기며 사이드바에서 수동으로 잠글 수도 있습니다.
변경·해제에는 현재 PIN이 필요하고, 5회 입력 실패 시 30초 동안 입력을 제한합니다.
잠금 화면에서 PIN을 초기화하는 기능은 제공하지 않습니다.

## 백업 내보내기

설정의 **백업 → 내보내기**에서 12자 이상의 비밀번호로 `.rdbackup` 파일을 만듭니다.
도서 정보와 표지 파일, ID·등록일·수정일을 보존하며, 기기 암호화 키와 PIN 설정은 포함하지 않습니다.
최대 32MiB를 지원합니다.

컴퓨터를 바꾸거나 운영체제를 재설치하기 전에 백업을 만들고 비밀번호를 별도로 보관하세요.
백업 비밀번호를 잃으면 복원할 수 없습니다.

## 복원

설정의 **복원 → 파일 선택**에서 백업 파일과 비밀번호를 확인합니다.
도서 수와 백업 시각을 검토한 뒤 `복원`을 입력해 진행합니다. PIN 사용 중에는 현재 PIN도 필요합니다.

- 복원은 현재 도서 목록 전체를 백업 내용으로 교체합니다.
- 현재 PIN 설정은 유지됩니다.
- 파일이나 비밀번호 검증에 실패하면 기존 도서는 변경하지 않습니다.
- 표지도 함께 검증하고 복원한 컴퓨터의 키로 다시 암호화합니다. 이미지가 없는 이전 백업도 지원합니다.
- 미리보기 후 서재가 변경되거나 5분이 지나면 파일을 다시 확인해야 합니다.

## 데이터 초기화

설정에서 `초기화` 확인 문구와 현재 PIN을 입력하면 도서·표지 파일·PIN 설정·화면 캐시를 삭제합니다.
외부 백업 파일과 운영체제 보안 저장소의 암호화 키는 유지됩니다. 잠긴 상태에서는 실행할 수 없습니다.

## 암호화 키를 잃었을 때

`books.vault`만으로는 다른 컴퓨터에서 서재를 열 수 없습니다. 백업 파일과 백업 비밀번호를 사용하세요.
기존 파일은 보존하고, 새 저장소에서 앱을 시작해 백업을 복원할 수 있습니다.

```sh
BOOK_MANAGER_DATA_DIR=/절대/새로운/빈폴더 pnpm dev
```

이 환경 변수는 개발 앱을 실제 서재와 분리해 실행할 때도 사용할 수 있습니다.
