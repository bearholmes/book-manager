# Frontend Lead 인계 — 방구석 도서관리 디자인 적용

## 요청과 현재 상태

사용자가 이 디자인 검토 내용을 바탕으로 `frontend-lead`의 구현 진행을 요청했다.
현재 design-director 세션에는 `message_agent` 도구가 없어 직접 메시지를 발송하지 못했다.
**이 문서는 실제 전달·수신·착수 확인을 의미하지 않는다.** 후속 담당자는 아래 파일과 현재 Git 상태를 먼저 확인한다.

현재까지 변경한 것은 디자인 명세·시안·검증 도구뿐이며 `src/`, `desktop/`, package/lockfile은 변경하지 않았다.
사용자의 기존 미추적 `IDEA.md`도 수정하지 않았다. 커밋·푸시는 요청되지 않았다.

## 먼저 읽을 자료

1. `DESIGN.md` — 디자인 방향, 양 모드 토큰, 서체·치수·상태·인계 기준.
2. `docs/design/REVIEW.md` — 후속 LNB/주제색 수정, 실제 검증 범위와 미검증 항목.
3. `docs/design/reading-room.html` — 수정 반영된 시안 원본.
4. `build/design-review/방구석 도서관리-디자인제안-v2.html` — 외부 요청 없이 열리는 최신 단일 HTML.
5. `docs/design/reading-room.tokens.json` / `.css` — 제안 토큰 생성물. 런타임에 그대로 import하지 않는다.

A/C는 방향 비교용 축소 보드다. 구현 기준은 **B. 조용한 개인 서재 + 아래 최신 수정**이다.
사용자의 구현 진행 요청을 기록하되, 모든 개별 치수·입력 플로우가 별도 승인되었다고 설명하지 않는다.
전체 입력 화면/네이티브 동작은 기존 기능을 온전히 배치한 뒤 실제 화면으로 다시 검토한다.

## 반드시 지킬 사용자 결정

- **제품명 ‘방구석 도서관리’ 변경 금지.** 현재 앱 로고도 교체하지 않는다.
- 다른 공통 서비스의 색/브랜드를 가져오지 않는 독립 프로젝트다.
- 책의 정체성을 유지한다. 번들 마루부리는 제목·도서명·메모, 시스템 산세리프는 조작부에 사용한다.
- 시스템/라이트/다크의 기존 선택·저장·OS 추종 동작을 보존한다.
- 라이트 LNB는 아래 새 선택 상태를 사용한다. 주제 구분색과 같은 역할로 묶지 않는다.
- **주제 칩의 기존 14색과 주제→색 배정은 보존한다.** 단색화는 철회된 초안이므로 적용하면 안 된다.
- 아이콘 변경은 허용되었지만 현재 권장안은 Lucide 규격 통일이다. 불필요한 교체/의존성 추가는 하지 않는다.

## 최신 라이트 LNB 규칙

| 상태 | 배경 | 아이콘·글자 |
| --- | --- | --- |
| 기본 | 투명, LNB 바탕 `#ECE8DF` | secondary `#565B53`, 500 |
| 비선택 hover | `#E3DFD5` | secondary 유지 |
| 현재 위치 | `#5B6B53` | `#FBF9F5`, 600 |
| 현재 위치 + hover | `#52624A` | `#FBF9F5`, 600 |
| keyboard focus | 현재/비현재 상태 유지 + 별도 2px focus outline, offset 2px | 상태에 맞는 글자 유지 |

- `aria-current="page"`는 현재 항목 하나에만 지정한다.
- 선택 항목을 hover 배경으로 덮어쓰지 않는다. 그림자·외곽 테두리·왼쪽 장식 띠는 추가하지 않는다.
- 다크 LNB의 외관은 이번 재검토 전과 동일하다: 선택 `#364C3E`, 글자 `#EEEDE5`, 비선택 hover `#343B32`.
- 보기 전환 등의 연한 `selected`는 유지하고, LNB에만 전용 `nav-*` 역할을 연결한다.
- 좁은 창/coarse pointer에서 보기 전환·탐색·아이콘 조작의 실제 클릭 영역은 44px 이상으로 확인한다.

## 주제 칩 보존 규칙

- 실제 원본: `src/shared/theme/tokens.css`의 `--color-category-1..14` 및 다크 override.
- 매핑 원본: `src/features/books/model/topic-colors.ts`, `src/shared/theme/data-colors.ts`.
- 기존 NFC 정규화·FNV-1a·mod 14를 재사용한다. 목록 순서나 필터 결과로 재배정하지 않는다.
- 같은 주제는 목록/표지/검색·정렬 전후에도 같은 슬롯을 사용한다. 유한 팔레트의 충돌은 허용하며 주제명은 항상 표시한다.
- 이번 시안은 기존 14색 값을 그대로 복원했다. 색을 줄이거나 순서를 바꾸지 않는다.
- 통일하는 것은 칩의 서체·안쪽 여백·모서리 규격이다. 선택/상태/주제 구분을 같은 토큰으로 뭉치지 않는다.
- 시안의 두 fixture 도서는 모두 프로그래밍이다. 두 칩이 같은 색인 것을 오류로 보고 책별 임의 색을 주면 안 된다.
- 시안의 ‘주제별 칩 색상’ 견본은 테스트 주제와 팔레트 검사다. 이를 실제 도서/주제 데이터로 제품에 추가하지 않는다.

## 구현 순서와 기술 제약

1. `AGENTS.md`, `docs/architecture.md`, 현재 컴포넌트/테마 구조를 먼저 확인한다.
2. 제안 값을 **기존 `src/shared/theme/tokens.css`의 RGB 채널 방식**으로 통합한다. 런타임 토큰 원본을 두 군데 만들지 않는다.
3. `DesktopLayout` → 공용 Button/Input/PageHeader/Table → Library/BookCard → Settings/Form/Overlays → Statistics/Lock/Notifications 순으로 적용한다.
4. 기존 Button/Input/Surface의 variant/size API와 인접 CSS Modules를 재사용한다. 화면마다 HEX·!important로 보정하지 않는다.
5. 다크 주요 버튼 글자는 `#1C3023`이지만 위험 버튼 글자는 흰색이다. 현재 공유 `on-solid`를 무조건 `on-action`으로 치환하면 danger 버튼이 잘못된다. 행동별 foreground 역할을 분리한다.
6. `--font-body`는 조작부용 산세리프, heading/book 역할은 MaruBuri로 분리한다. 표·카드의 도서명과 메모에 세리프를 명시한다.
7. 기존 가상 도서 그리드의 JS 열 계산·ResizeObserver·실제 행 측정을 유지한다. 사이드바/여백 변경 뒤 컨테이너 폭 및 긴 제목을 다시 검증한다.
8. CRUD·검색·ISBN 보조 조회·PIN·백업/복원/초기화·실제 데이터 구조는 변경하지 않는다. 2필드 입력 시연을 실제 BookForm 대신 구현하지 않는다.
9. 기존 SidePanel/Modal의 포털·inert·포커스 trap/복원·Escape 수명주기를 유지한다. 짧은 창에서도 제목/닫기/취소·저장이 접근 가능해야 한다.
10. 차트의 6색 제안 예시를 이유로 기존 10슬롯이나 범주 의미를 임의 축소하지 않는다. 주제는 14색 보존이 명시된 상태다.
11. 네이티브 타이틀바와 창 버튼은 OS가 소유한다. HTML 신호등·가짜 드래그 바·유리 효과를 추가하지 않는다.
12. 모션은 짧은 상태 전환에만 사용하고 CSS/JS 모두 reduced motion을 존중한다.

## 현재까지의 검증 — 구현 완료 증거와 구분

- 제안 색상 55역할/모드, 불투명 단색 대비 138쌍 통과.
- 제안 검사기/팔레트·매핑 보존 Node 테스트 6개 통과.
- `pnpm check` 통과. 기존 Vitest 22파일/112테스트 통과 기록이 있다.
- 브라우저에서 시안의 검색/보기/상세/입력 상태, 테마, LNB 상태·전환, 주제색 양 모드와 슬롯 일치를 확인했다.
- **실제 Electrobun 앱에 적용한 검증은 아직 전혀 아니다.** 시안 결과를 네이티브/전체 접근성 적합성으로 보고하지 않는다.

## 구현 후 수용 기준

- 1360×900, 1024×768, 800×600, 640×700, 360×780 및 실제 200% 확대에서 도구 충돌·가로 넘침·잘림 확인.
- 라이트/다크의 서재 목록/표지, 상세, 전체 입력 폼, 설정과 핵심 상태를 실제 렌더링으로 검토.
- LNB selected/hover/focus 분리, 14개 주제 칩과 stable mapping, danger/primary foreground, 오류 문구·경계·포커스 확인.
- 시스템 외관 전환과 첫 프레임 테마, 키보드 이동·모달 복원, reduced motion 확인. VoiceOver/고대비 등 미검증 항목은 명시.
- `pnpm check`, 관련 Vitest 및 E2E 실행. 변경 기능에 맞는 회귀 테스트 추가.
- `pnpm build` 및 패키지 renderer 일치 확인 후 실제 macOS 앱 검증. 브라우저 확인을 네이티브 검증으로 부르지 않는다.
- 적용 후 `docs/design-system.md`와 DESIGN.md의 상태/원본 관계를 갱신해 상충 지침을 남기지 않는다.
- 결과 보고: 변경 파일, 실제 실행 명령과 결과, 양 모드 스크린샷, 미검증/보류 항목. 커밋·푸시는 별도 요청 전 하지 않는다.

디자인 검토가 필요한 부분은 구현 화면과 구체적 위치를 남겨 design-director에 요청한다.
