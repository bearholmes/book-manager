# 방구석 도서관리 — 디자인 제안 검토 기록

## 상태와 범위

**사용자 승인 전 디자인 제안. 제품명·기존 앱 로고 유지. 실제 앱에는 적용하지 않았다.**
독립 프로젝트의 전용 방향이며 다른 공통 서비스의 브랜드를 사용하지 않는다.

이 단계의 산출물은 컨셉 비교, 추천안의 라이트/다크 의미 토큰, 로컬 인터랙티브 시안,
화면·컴포넌트·접근성·모션·구현 인계 규칙이다. CRUD/보안/백업 등의 재구현이 아니다.

## 파일과 원본

| 파일 | 역할 |
| --- | --- |
| `DESIGN.md` | 승인 전 디자인 명세·색상 원본·근거·금지 규칙·인계 기준 |
| `docs/design/reading-room.html` | 로컬 시안. B안 상세 + A/C 축소 구성 비교 + 색상/서체/상태 견본 |

| `docs/design/verify-design.test.mjs` | 양방향 색상 키 검증과 실패 시 기존 출력 보존에 대한 Node 회귀 테스트 |

| `build/design-review/방구석 도서관리-디자인제안.html` | 다운로드용 단일 파일. 빌드 생성물이므로 Git 제외 |

현재 제품의 런타임 원본은 여전히 `src/shared/theme/tokens.css`다. 이 제안 파일을 앱이 import하지 않는다.
승인 후에는 제안 내용을 해당 런타임 원본으로 통합하고 기존 `docs/design-system.md`를 명시적으로 갱신해야 한다.
두 문서의 충돌 시 이번 제안이 자동으로 기존 규칙을 덮어쓰지 않는다.

## 확인한 현재 상태

- README와 실제 기능: 도서·표지·서지/구매 정보·검색/필터·통계·설정·PIN·백업/복원.
- 읽은 구현: DesktopLayout, Library, BookTable, BookCard, VirtualizedBookGrid, Settings,
  BookFilters, BookDetailModal, Button, Input, PageContent, theme CSS 및 desktop window 구성.
- 현재 앱의 브라우저 개발 모드를 **별도 임시 데이터 디렉터리와 테스트 키**로 실행해 빈 서재의 라이트/다크를 관찰했다.
  실제 사용자의 책 데이터·키체인·외부 계정은 읽거나 수정하지 않았다. 검사 후 해당 개발 서버는 종료했다.
- 현재 마루부리 번들·라이선스와 앱 로고를 재사용한다. 외부 CDN 폰트 요청과 새 UI 의존성 없음.
- `IDEA.md`는 작업 시작 시 존재한 사용자 미추적 파일이며 수정하지 않았다.

### 설계 진단

1. 기존 문서에는 Catalyst 작업 화면 규칙과 Slite 색상 레퍼런스가 혼합되어 있다.
2. 토큰의 종이색·코랄 선택색·회색 행동색, 다크의 청회색 주요 버튼 사이에 공통 의미가 약하다.
3. 모든 크기의 조작부와 책 제목이 동일한 세리프 스택을 사용해 ‘책의 표현’과 ‘도구의 조작’의 구분이 적다.
4. 외곽 카드 프레임, 넓은 사이드바, 페이지 여백은 웹 작업 화면의 인상이 강하다.

이는 디자인 판단이며 장애/접근성 위반을 자동으로 의미하지 않는다.

## 레퍼런스 사용 원칙

공식 Bear Mac 이미지와 Things macOS 26 이미지를 직접 열어 탐색·목록·그룹의 위계를 관찰했다.
getdesign.md의 Notion/Claude/Oura 분석에서 표면·타이포 역할과 명세 방식을 참고했다.
getdesign.md는 각 브랜드의 공식 디자인 시스템이 아닌 제3자 분석이다.
Oura는 공개 소개에 나온 종이색·세리프/산세리프 방향만 참고했으며 전체 유료 자료를 확인한 것으로 주장하지 않는다.

21st.dev 공개 카탈로그와 Hover Preview 상세 소개를 확인했지만 코드를 복사하거나 설치하지 않았다.
이미지 hover 미리보기는 필수 정보가 포인터에만 숨는 문제가 있어 이번 기본안에 넣지 않았다.
검색·선택·패널 전환에 필요한 짧은 모션만 자체 시안에서 다룬다.
정확한 출처 링크와 채택/미채택 범위는 DESIGN.md에 있다.

### 실제 브라우저에서 확인한 시안

테스트 도서는 `src/test/mockData.ts`의 클린 코드·리팩터링 **두 건**이다.
서지 사실을 재검증한 것이 아니며 실제 서재 규모처럼 보이는 임의 수치나 표지를 추가하지 않았다.

- 검색 1건 결과 → 검색 없음 → 초기화 2건 복구.
- 구매처 필터, 도서명순 정렬, 목록/표지 전환과 표지 없음 대체 상태.
- 도서 상세 열기, Escape 닫기, 원래 도서 버튼으로 포커스 복원.
- 입력 시연의 필수 항목 오류, 정상 입력 피드백, 실제 도서가 저장되지 않음.
- 양 모드의 빈 서재/불러오는 중/오류/재시도.
- 설정 테마 선택과 상단 시안 선택의 동기화. 시스템 외관 변경 시 light/dark 반영.
- fixture에서 계산한 전체 2권/주제/구매처 분포. 통계 차트 완성 시안이 아님.
- Command+F 검색 포커스, 대화상자 내부 키보드 포커스와 Escape.
- CSS `prefers-reduced-motion` emulation에서 스피너 animation none·버튼 transition 0s.
- 주요 버튼 default/hover/active의 계산된 배경과 foreground 일치. **hover/active 값은 CDP의 CSS pseudo-state 강제 설정으로 검사**했다.
  네이티브 포인터 연속 제스처의 전수 검증으로 주장하지 않는다.
- 입력 사이드패널의 오른쪽 배치와 오류 경계색, 비교/토큰/상태 disclosure의 실제 열림 및 상태 피드백.
- 1360×900 / 1024×768 / 800×600 / 640×700 / 360×780 / 680×450에서 문서 가로 넘침 없음.
  680×450은 작은 유효 작업 공간의 보조 검사이며 **실제 브라우저 200% 확대 검증의 대체가 아니다**.
- 라이트/다크 데스크톱 스크린샷과 360px 전체 보드를 직접 육안 검토. 좁은 창의 필터 라벨 잘림을 수정했다.
- 오프라인 단일 HTML을 file://로 열어 제목, 도서 2행, 마루부리 로드, 로고 로드 확인.
  초기 로드의 외부 HTTP 요청 0건, 명세/대비/폰트 라이선스 다운로드 3개 내장 확인.

브라우저 관찰·assertion 묶음은 21개를 수행했다. 이 숫자는 사용자 시나리오별 assertion 묶음이며
별도의 정식 E2E 테스트 파일 수나 모든 상태 조합의 개수가 아니다. 원시 실행 증거/스크린샷은
프로필 scratch 경로에 두고 Git에 포함하지 않는다.

### 검증 중 보완

- 다크 선택 표면의 보조 메타 글자가 4.5:1에 못 미쳐 `dark-muted`를 밝게 조정.
- 라이트 비활성 라벨은 기준 예외에 기대지 않고 별도 `on-disabled`로 4.5:1 이상 확보.
- 테마 전환 중 버튼 전경/배경이 다른 타이밍으로 보간되지 않도록 테마 변경 시 전환 억제.
- 360px 필터 3개를 한 줄에 압축하지 않고 2열 + 정렬 행으로 배치.
- 입력 오류는 문구/aria-invalid뿐 아니라 토큰화된 경계도 함께 표시. 포커스 외곽선은 유지.

## 라이트 LNB 및 주제 칩 재검토

- 기존 라이트 선택 배경 `#E3EBE3`와 LNB 바탕 `#ECE8DF`는 명도 대비가 거의 1:1로,
  텍스트 가독성과 별개로 현재 위치의 식별성이 약했다. 종이색+외곽선도 비교했으나 입력창처럼
  보여 제외했다. 새 선택은 `#5B6B53` 채움 + `#FBF9F5` 아이콘·글자로, 배경 경계 4.68:1,
  글자 5.44:1이다. 비선택 호버는 `#E3DFD5`, 선택 호버는 `#52624A`, 포커스는 별도 외곽선이다.
- LNB 전용 nav-* 토큰을 분리했다. 일반 보기 전환의 연한 선택색과 다크 LNB의 기존 외관은 유지한다.
  세 탐색 항목 전환·단일 aria-current·선택/비선택 호버·포커스·360px 창을 브라우저에서 검사했다.
- 주제 칩을 단색으로 통일한 초기 제안은 **사용자의 기존 분류 색상을 없애는 미합의 변경**이었다.
  해당 결정을 철회했다. 기존 런타임의 14색·양 모드 대응·NFC/FNV 배정 규칙을 시안에 복원했다.
  이름별 색상 인덱스는 변경하지 않는다. 원래 런타임 코드 자체는 이 작업 내내 변경하지 않았다.
- 초기 4개 Node 회귀 테스트에 기존 팔레트 전체 일치와 매핑 구현 일치 검사를 추가해 **6개 통과**.
  브라우저에서도 프로그래밍→13, 소설→14, 자기계발→8과 목록/표지 간 동일한 배정을 확인했다.
  14색 견본은 디자인 검사 용도이며 실제 서재의 주제 수나 소장 도서를 뜻하지 않는다.
- 주제 칩의 통일 대상은 모양·크기·글자·간격이다. 주제 구분 색과 LNB 현재 위치 색을 동일시하지 않는다.

## 독립 검토 후 보완

정적 독립 검토에서 지적한 네 항목을 현재 파일과 대조하고 다음과 같이 처리했다.

1. **입력 구조/짧은 창:** 검토 중간본의 중앙 입력 모달은 이미 오른쪽 사이드패널로 변경되어 있었다.
   추가로 패널 안에서는 본문만 스크롤되도록 정리해 제목·닫기·하단 닫기 영역을 유지했다.
   전체 BookForm과 실제 취소/저장 동작은 이번 컨셉 승인 범위에서 제외함을 DESIGN.md에 명시했다.
2. **비색상 원본/입력 글자:** 입력 값은 명세와 동일한 14px, 선택·조작 요소는 13px로 구분했다.
   반경과 입력/UI 글자 크기는 DTCG에서 생성한다. OS 확장 서체·모션 및 나머지 HTML 수치는
   문서 기준의 수동 관리임을 명시했다. CLI export의 숫자 lineHeight 누락도 기록했다.
3. **검사 사각지대:** 원본↔DTCG 색상 키 집합을 양방향 비교한다. 오류가 나면 CSS·보고서를 쓰기 전에
   실패하고 이전 출력을 보존한다. 비색상 전체 동기화 보증은 하지 않는다.
   정상 / 양 모드의 비검사 역할 동시 누락 / export에만 추가 / 대비 실패의 Node 회귀 테스트 **4개 통과**.
4. **44px 타깃:** 좁은 창과 coarse pointer에서 보기 전환을 실제 44×44px로 확대했다.
   도서 제목 클릭 영역, 아이콘 닫기와 초기화 영역도 해당 조건에서 확대했다.

후속 브라우저 실측: 360px 창과 800px coarse-pointer 조건에서 보기 전환 44×44px,
도서명 버튼 높이 44px, 검색 입력 14px/선택 상자 13px, 가로 넘침 없음.
640×360 패널에서 본문을 122px 스크롤한 전후에도 제목 위쪽 25px·하단 행동 끝 335px를 유지했다.
초기 21개 관찰 묶음 외의 추가 검사이며, 실제 네이티브 앱 검증은 여전히 아니다.

## 자기 검토 — 장식과 구성

10개 anti-slop 항목 중 해당 **0개라는 자체 판단**. 객관적 품질 점수나 사용자 승인 점수가 아니다.
주 표면은 Explore, 비교 영역만 Compare다. 마케팅 히어로/기능 카드/장식 수치/광택/무의미한 모션 없음.
도구에 시스템 폰트를 쓴 것은 작은 한글 UI와 OS 조작 가독성을 위한 명시적 결정이다.
문서의 첫 문장은 제안서 표제이며 앱 안의 마케팅 영역이 아니다. 세 가지 축소 보드는 서로 다른 구성 비교다.

## 재생성

프로젝트의 고정 Node 버전을 선택한 후 실행한다. 제품의 package.json에 별칭/의존성을 추가하지 않았다.

```sh
nvm use
pnpm dlx @google/design.md@0.4.0 lint DESIGN.md
pnpm dlx @google/design.md@0.4.0 export --format dtcg DESIGN.md > docs/design/reading-room.tokens.json
node docs/design/verify-design.mjs
node --test docs/design/verify-design.test.mjs
pnpm exec biome format --write docs/design/reading-room.tokens.json docs/design/reading-room.tokens.css
node docs/design/package-design.mjs
pnpm check
pnpm test --run
```

시안 원본은 프로젝트 안에서 열거나, 생성한 단일 HTML을 브라우저에서 직접 열 수 있다.
원본의 상대경로 자산은 저장소 구조를 전제로 하므로 HTML 하나만 따로 복사할 때는 생성한 단일 파일을 쓴다.
